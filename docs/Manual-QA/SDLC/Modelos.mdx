## Métodologías
Una metodología es un conjunto de procedimientos, técnicas, herramientas y reglas diseñadas de forma lógica para guiar y optimizar
la realización de un proyecto o una investigación. Es la estructura o "hoja de ruta" que define cómo se debe trabajar paso a paso 
para alcanzar un objetivo específico de manera eficiente.

### Componentes Clave de una Metodología

- **Marcos de trabajo:** Definen las reglas generales, los roles de los integrantes y los entregables de cada etapa.

- **Herramientas específicas:** Instrumentos técnicos o plataformas de software necesarios para ejecutar las tareas diarias.

- **Técnicas y prácticas:** Los métodos exactos para resolver problemas, estimar tiempos o evaluar la calidad del trabajo.

- **Procesos estandarizados:** Los pasos fijos y repetibles que garantizan un resultado predecible y consistente.

### Metodologías tradicionales 

La metodología tradicional (también conocida como predictiva o en Cascada) es un enfoque de gestión de proyectos donde las fases se ejecutan de forma 
secuencial y lineal. Cada etapa debe completarse al 100 % antes de poder iniciar la siguiente, bajo la premisa de que los requisitos del proyecto están 
totalmente definidos desde el inicio y no cambiarán.

#### Las 5 Fases Típicas del Ciclo en Cascada
 - **Requisitos:** Definición y documentación exhaustiva de todo lo que el cliente necesita al inicio.
 - **Diseño:** Planificación de la arquitectura técnica, planos, especificaciones o maquetas del producto.
 - **Implementación:** Ejecución física del trabajo o desarrollo del producto siguiendo el diseño previo.
 - **Verificación:** Pruebas rigurosas de control de calidad para asegurar que el resultado cumple el contrato.
 - **Mantenimiento:** Entrega final al cliente y soporte o corrección de fallas durante su uso operativo.

#### Ventajas

- **Claridad:** Los objetivos, el presupuesto y las fechas de entrega están fijados firmemente desde el primer día.
- **Documentación:** Cada fase genera registros detallados, lo que facilita el traspaso de información entre equipos.
- **Facilidad de gestión:** Al ser un avance lineal, es muy fácil medir el progreso del proyecto en una línea de tiempo.

#### Limitaciones principales.

- **Rigidez:** Cambiar un requisito a mitad del proyecto es sumamente costoso y requiere renegociar contratos.
- **Riesgo tardío:** El cliente final no ve el producto real hasta las fases finales, aumentando el riesgo de insatisfacción.
- **Bloqueos:** Si una fase se retrasa, todo el cronograma posterior se desplaza automáticamente.


#### Cascada (Waterfall)

El modelo en cascada es un modelo secuencial que divide el desarrollo de software en fases predefinidas. Cada fase debe completarse antes de que pueda comenzar 
la siguiente, sin que haya solapamiento entre ellas. Cada fase está diseñada para realizar una actividad específica durante el ciclo de vida del desarrollo de 
software (SDLC)

#### Modelo V

El modelo V es un modelo SDLC altamente disciplinado que incluye una fase de pruebas paralela a cada fase de desarrollo. El modelo V es una extensión del 
modelo en cascada, donde el desarrollo y las pruebas de software se ejecutan de forma secuencial. También se conoce como modelo de validación o verificación.

#### Modelo espiral.
El modelo espiral es un enfoque del ciclo de vida del desarrollo de software (SDLC) que enfatiza la gestión de riesgos. Implica ciclos iterativos de planificación, 
análisis de riesgos, ingeniería y evaluación. Cada ciclo se basa en el anterior, refinando gradualmente el software y mitigando los riesgos potenciales a medida 
que avanza el proyecto.

### Metodologías ágiles

El modelo ágil se refiere a un enfoque de desarrollo de software basado en el desarrollo iterativo. Los métodos ágiles dividen las tareas en iteraciones o partes 
más pequeñas que no implican una planificación a largo plazo. El alcance y los requisitos del proyecto se definen al inicio del proceso de desarrollo. Los planes 
relativos al número de iteraciones, la duración y el alcance de cada una se definen claramente con antelación.

La metodología de desarrollo de software Agile es uno de los procesos más sencillos y eficaces para convertir la visión de una necesidad empresarial en soluciones de software.
Las metodologías ágiles son un enfoque de gestión de proyectos que se basa en la flexibilidad, la entrega de valor en periodos cortos de tiempo y la 
colaboración constante. Nacieron formalmente en el año 2001 con el Manifiesto Ágil, como respuesta a la rigidez y los retrasos de la metodología tradicional en el 
desarrollo de software.

#### Ventajas

 - **Entregas rápidas:** El cliente no tiene que esperar meses para ver el resultado; recibe avances reales de forma constante.
 - **Alta adaptabilidad:** Si las necesidades del mercado o del cliente cambian, el equipo puede pivotar y ajustar el rumbo en el siguiente ciclo sin perder dinero.
 - **Mayor satisfacción:** Al involucrar al cliente en las revisiones de cada ciclo, el producto final se alinea perfectamente con sus expectativas.

Existen varios modelos en el ciclo de vida del desarrollo de software (SDLC), cada uno con sus características y enfoques, Las mas reconocidas son:

- **Agile:** Se enfoca en la adaptabilidad, la colaboración continua y la entrega incremental del producto. Permite responder rápidamente a los cambios y 
    mejora la eficiencia del desarrollo.

- **Scrum:** En las pruebas de software es una metodología para la creación de aplicaciones de software complejas. Proporciona soluciones sencillas para la ejecución 
    de tareas complicadas. Scrum ayuda al equipo de desarrollo a centrarse en todos los aspectos del desarrollo del producto de software, como la calidad, el rendimiento,
    la usabilidad, etc. Ofrece transparencia, inspección y adaptación durante el desarrollo del software para evitar la complejidad.

- **Kanban:** Es un marco de trabajo muy popular para el desarrollo en la metodología de desarrollo ágil de software. Proporciona una forma transparente de visualizar 
    las tareas y la capacidad de trabajo de un equipo. Utiliza principalmente tableros físicos y digitales para que los miembros del equipo puedan visualizar 
    el estado actual del proyecto en el que están trabajando.
    Un tablero Kanban es una herramienta de gestión de proyectos ágiles diseñada para ayudar a visualizar el trabajo, limitar el trabajo en curso y maximizar 
    la eficiencia.

- **Extreme Programming (XP):** La Programación Extrema (XP) es un marco de desarrollo de software ágil que busca producir software de mayor calidad y mejorar 
    la calidad de vida del equipo de desarrollo. XP es el marco ágil más específico en cuanto a las prácticas de ingeniería adecuadas para el desarrollo de software.

- **SAFe (Scaled Agile Framework):** Scaled Agile Framework (SAFe) es una base de conocimientos en línea de acceso gratuito que permite aplicar prácticas lean-ágiles 
    a nivel empresarial. Proporciona una experiencia sencilla y ágil para el desarrollo de software. Se trata de un conjunto de patrones de organización y flujo de 
    trabajo diseñados para guiar a las empresas en la implementación a gran escala de prácticas lean y ágiles. Está dividido en tres segmentos: Equipo, Programa y 
    Portafolio.


### Metodologías de prueba

Las metodologías de prueba son enfoques estructurados para la prueba de software, cada uno con su propia filosofía y técnicas. El Desarrollo Dirigido por Pruebas 
(TDD) implica escribir pruebas antes de escribir el código, asegurando que este cumpla con requisitos específicos. El Desarrollo Dirigido por Pruebas de 
Aceptación (ATDD) se centra en definir criterios de aceptación en colaboración con las partes interesadas, impulsando el desarrollo desde una perspectiva empresarial.
El Desarrollo Dirigido por Comportamiento (BDD) utiliza descripciones en lenguaje natural del comportamiento del sistema para crear pruebas, promoviendo una mejor 
comunicación entre desarrolladores, evaluadores y partes interesadas del negocio. El Análisis de Causa Raíz (RCA) es un proceso sistemático para identificar las causas 
subyacentes de problemas o defectos, con el objetivo de prevenir su recurrencia en lugar de solo abordar los síntomas.

#### TDD - Desarrollo guiado por pruebas

El desarrollo guiado por pruebas (TDD, por sus siglas en inglés) es un enfoque de desarrollo de software en el que se crean casos de prueba para especificar y validar 
el funcionamiento del código. En términos sencillos, se crean y prueban casos de prueba para cada funcionalidad. Si una prueba falla, se escribe un nuevo código para 
superarla, logrando así un código simple y libre de errores.

#### Desarrollo guiado por pruebas de aceptación (ATDD)

ATDD es un enfoque colaborativo en el que todo el equipo define los criterios de aceptación antes de que comience el desarrollo. Estos criterios se transforman en 
pruebas automatizadas que guían el proceso de desarrollo. El objetivo es garantizar que el software cumpla con las necesidades y expectativas específicas de las partes 
interesadas.

#### Desarrollo impulsado por el comportamiento.

El desarrollo guiado por el comportamiento (BDD, por sus siglas en inglés) es un proceso de desarrollo de software que enfatiza la colaboración entre 
desarrolladores, evaluadores y partes interesadas del negocio. Se centra en definir el comportamiento esperado del software en un lenguaje sencillo, 
utilizando ejemplos para ilustrar la funcionalidad deseada. Estos ejemplos se traducen posteriormente en pruebas automatizadas, lo que garantiza que 
el software cumpla con los requisitos acordados.

#### Análisis de la causa raíz

El análisis de la causa raíz (ACR) es un método sistemático de resolución de problemas que busca identificar las razones fundamentales detrás de un problema o evento. 
Va más allá de abordar los síntomas inmediatos para descubrir los factores clave que lo originaron y así prevenir su recurrencia. Al comprender las causas subyacentes, 
se pueden implementar soluciones efectivas para eliminar o mitigar el riesgo de que ocurran problemas similares.
