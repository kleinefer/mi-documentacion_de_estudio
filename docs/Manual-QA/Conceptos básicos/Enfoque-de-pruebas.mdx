## Enfoques de prueba
El método de prueba tiene dos técnicas:

**Proactivo:** un enfoque en el que el proceso de diseño de pruebas se inicia lo antes posible para encontrar y corregir los defectos antes de que se cree 
la versión final.
**Reactivo:** un enfoque en el que las pruebas no se inician hasta que se han completado el diseño y la codificación.

Para implementar las pruebas funcionales se suelen utilizar tres enfoques:

1.  Pruebas de caja negra
2.  Pruebas de caja blanca
3.  Pruebas de caja gris


### Pruebas de caja blanca (white box testing)

Las pruebas de caja blanca son una técnica que consiste en probar la estructura interna, el diseño y la codificación del software para verificar el flujo de 
entrada-salida y mejorar el diseño, la usabilidad y la seguridad. En las pruebas de caja blanca, el código es visible para los evaluadores, por lo que también se 
las conoce como  Clear box testing, Open box testing, Transparent box testing, Code-based testing, and Glass box testing.

### Prueba de caja gris (gray box testing)

Las pruebas de caja gris son una técnica de prueba de software que permite evaluar un producto o aplicación con conocimiento parcial de su estructura interna. 
Su objetivo es detectar e identificar defectos derivados de una estructura de código inadecuada o un uso incorrecto de la aplicación.

### prueba de caja negra (black box testing)

Las pruebas de caja negra son un método de prueba de software en el que se evalúan las funcionalidades de las aplicaciones sin conocer la estructura interna del 
código, los detalles de implementación ni las rutas internas. Este método se centra principalmente en la entrada y salida de las aplicaciones y se basa completamente 
en los requisitos y especificaciones del software. También se conoce como pruebas de comportamiento.
