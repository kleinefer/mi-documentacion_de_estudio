# Pruebas de software

Las **pruebas de software** son un proceso que consiste en **evaluar una aplicación o sistema para comprobar que funciona correctamente, cumple los requisitos establecidos y está libre de defectos o errores que puedan afectar su funcionamiento**.

Su objetivo principal es garantizar la calidad del software antes de que llegue a los usuarios, verificando que las funcionalidades operen como se espera y que el sistema sea confiable, seguro y eficiente.

Por ejemplo:

* Si un usuario inicia sesión con credenciales correctas, la prueba verifica que pueda acceder al sistema.
* Si ingresa una contraseña incorrecta, la prueba confirma que se muestre el mensaje de error correspondiente.
* Si realiza una compra en línea, la prueba valida que el pedido se registre correctamente y el pago se procese sin inconvenientes.

### ¿Para qué sirven las pruebas de software?

* Detectar errores antes de la entrega del producto.
* Verificar que el software cumpla los requisitos funcionales y no funcionales.
* Mejorar la calidad, estabilidad y confiabilidad del sistema.
* Reducir costos de mantenimiento al encontrar fallos de manera temprana.
* Garantizar una buena experiencia para el usuario.

:::note
 **Las pruebas de software son un conjunto de actividades diseñadas para identificar defectos y 
 asegurar que una aplicación funcione correctamente, cumpla con los requisitos del negocio y ofrezca un producto de calidad al usuario final**.
::: 


## 1. Pruebas funcionales
  
  Las pruebas funcionales son un tipo de prueba de software que verifica que cada funcionalidad de una aplicación 
  opere de acuerdo con los requisitos funcionales, las reglas de negocio y las especificaciones definidas. 
  Se enfocan en comprobar que el sistema haga lo que debe hacer, sin analizar cómo está implementado internamente.

Estas pruebas se realizan desde la perspectiva del usuario, validando las entradas, el procesamiento y las 
salidas del sistema. Generalmente se basan en la técnica de caja negra (Black Box Testing), ya que el 
tester no necesita conocer el código fuente.

### Objetivos de las pruebas funcionales

- Verificar que cada funcionalidad cumpla con los requisitos establecidos.
- Detectar errores en los procesos de negocio.
- Validar que las entradas sean procesadas correctamente.
- Comprobar que el sistema genere las salidas esperadas.
- Asegurar que el usuario pueda utilizar la aplicación sin inconvenientes.

### Ejemplos de pruebas funcionales

- Validar el inicio de sesión con credenciales válidas e inválidas.
- Verificar el registro de un nuevo usuario.
- Comprobar el funcionamiento del proceso de compra.
- Validar el cálculo correcto de impuestos o descuentos.
- Confirmar el envío de correos electrónicos después de una acción.
- Verificar la generación de reportes.

### Características

- Se centran en el comportamiento del sistema.
- Evalúan funcionalidades completas.
- No requieren acceso al código fuente.
- Se ejecutan con base en casos de prueba derivados de los requisitos.

## 2. Pruebas no funcionales

Las pruebas no funcionales son un tipo de prueba de software que evalúa las características de calidad del 
sistema, como el rendimiento, la seguridad, la usabilidad, la confiabilidad y la compatibilidad. A diferencia 
de las pruebas funcionales, no verifican qué hace el software, sino cómo lo hace **bajo diferentes condiciones.**

Su objetivo es garantizar que la aplicación ofrezca una experiencia de uso eficiente, estable y segura, 
incluso cuando se enfrenta a altas cargas de trabajo o diferentes entornos de ejecución.

### Objetivos de las pruebas no funcionales

- Evaluar el rendimiento y la estabilidad del sistema.
- Verificar la seguridad de la aplicación y la protección de los datos.
- Comprobar la facilidad de uso para los usuarios.
- Validar la compatibilidad con distintos dispositivos, navegadores y sistemas operativos.
- Garantizar la disponibilidad y confiabilidad del software.

### Características
- Evalúan atributos de calidad del software.
- Se ejecutan generalmente después de validar las funcionalidades principales.
- Ayudan a identificar problemas que pueden afectar la experiencia del usuario.
- Pueden realizarse de forma manual o mediante herramientas especializadas.
